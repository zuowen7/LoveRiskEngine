# Getting Started — LoveRiskEngine (English)

A five-minute path from `pip install` to a daily decision-support habit.
For the philosophy and full command reference, see the [README](../README.md);
the canonical roadmap lives in [`ARCHITECTURE_AND_PLAN.md`](ARCHITECTURE_AND_PLAN.md).

## 1. Install

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"                                 # or ".[dev,pretty]" for optional rich output
```

Zero runtime dependencies; `rich` (optional) only prettifies `status`/`review`
on real terminals.

## 2. Initialize and create a relationship

```bash
lre init                                             # prints the exact database path
lre relationship add "Alex" --kind LOVER
```

Kinds: `LOVER / FRIEND / PARENT / BOSS / MENTOR / COLLEAGUE / STRANGER`.
The kind selects a profile — display context (power asymmetry / exit cost
bands), a 90-day promise window (BOSS/MENTOR/COLLEAGUE), and earlier warnings
for high-exit-cost kinds. Ordinals, never numbers.

## 3. The daily loop

```bash
# Record: observation, interpretation, and at least one alternative.
lre observe Alex --observation "cancelled our plans twice this week" \
    --interpretation "losing interest" --alternative "heavy work deadline" \
    --confidence 4 --signal-type COSTLY

# Structured claims power the contradiction tracker.
lre observe Alex --observation "said he is single" --claim "relationship_status=single"
lre observe Alex --observation "mentioned his wife" --claim "relationship_status=married"
lre contradictions Alex --save

# Your own state and exposure, kept strictly separate.
lre state set Alex --attraction 8.5 --trust 4 --uncertainty 7 --emotional ANXIOUS
lre exposure set Alex --time 3 --emotional 4

# See everything and run a structured review.
lre status Alex
lre review Alex
lre history Alex
```

`review` proposes one of `CONTINUE_OBSERVING / WAIT / PAUSE /
DECREASE_EXPOSURE / EXIT`; `EXIT` only ever comes from a recorded hard-boundary
hit. Blocking decisions start a cooldown that gates exposure-raising actions
(overrideable, always logged).

## 4. Precommit your own lines

```bash
lre boundary add --description "never disrespects my stated boundaries" --severity HARD
lre boundary hit B001 --relationship Alex --evidence "mocked my boundary in front of friends"
lre verify add Alex --item "introduced me to their friends"
lre verify check V001          # confirm costly signals you have actually verified
```

## 5. Back up — one command

```bash
lre export backup.json        # lossless, SHA-256 checksummed
lre restore backup.json       # replaces the whole database; corrupt/wrong-version files are refused
lre db check                  # integrity + foreign-key checks
```

Treat the bundle like a diary file: encrypted storage, backed up with the rest
of your important data.

## 6. Language & completion

```bash
LRE_LANG=zh lre status Alex            # Chinese UI for this invocation (setx LRE_LANG zh to persist)
eval "$(lre completion bash)"          # bash completion generated by the installed lre itself
```

## 7. Auditing your own judgment

```bash
lre counterfactual Alex                # list past reviews
lre counterfactual Alex --review RV001 # re-run that review against the evidence
                                       # available at the time (today's rules, past evidence)
```

## FAQ

- **Where is my data?** `lre init` prints the path: the platform data
  directory by default; `LRE_DB_PATH` overrides.
- **Is anything ever deleted?** No. Boundaries retire, observations append,
  windows affect display only. Exports are lossless.
- **Why are stored review notes in English even in Chinese mode?** Canonical
  records stay English — they are evidence; only display is localized.
